# Evidence audit for the website

Checked 2026-09-13 against original reports and papers. These are historical observations, not measured benefits of Perigee. Website implementation: `src/components/evidence.tsx`.

| Supplied claim | Finding and editorial decision |
| --- | --- |
| 59% of all spacecraft anomalies involve attitude control and power | Retain with scope: AOCS plus power account for 59% of 156 recorded on-orbit failures from 1980–2005. AOCS includes orbit control; this is not a census of every anomaly. [Tafazoli, original paper, Fig. 1 and surrounding text](https://www.researchgate.net/publication/245139911_A_study_of_on-orbit_spacecraft_failures). |
| 158 power failures, 1990–2013, costing $4.4 billion | Two studies were conflated. The 2013 abstract reports 158 failures, but the attached 2006 paper reports 64 incidents and $4.4 billion for 1990–2006. Use the 2006 population with the cost, not 158. Reported losses are not inflation-adjusted or an estimate of preventable damage. [2006 author-uploaded paper, results and Table 1](https://www.researchgate.net/profile/Geoffrey-Landis/publication/268472596_Tabulation_of_Power-Related_Satellite_Failure_Causes/links/59d503834585150177fc8ef1/Tabulation-of-Power-Related-Satellite-Failure-Causes.pdf), [2013 abstract](https://www.researchgate.net/publication/268472596_Tabulation_of_Power-Related_Satellite_Failure_Causes). |
| 68% of deployables failures cause mission/performance loss | The NASA-indexed earlier version reports 68% / 32% for 53 spacecraft. The conference version reports 67% / 33% for 54 spacecraft. Website uses the directly retrieved conference version: 67%, not a fleet-wide failure probability. [Rivera & Stewart, ESMATS 2021, abstract and p. 5](https://www.esmats.eu/esmatspapers/pastpapers/pdfs/2021/rivera.pdf), [earlier NASA-indexed version](https://ntrs.nasa.gov/api/citations/20210020397/downloads/Alphonzo%20Stewart-%20Final%20Paper.pdf). |
| Around nine in ten total GEO losses occur on orbit | Reject. The cited patent's table contains 328 **launches**, of which 264 succeeded and 64 suffered loss. Launch/boost losses: 21 + 13 = 34. Checkout/operations losses: 19 + 11 = 30. Calculated from that table, checkout/operations are 30 / 64 = 46.875% of loss cases, not 89.6%. The patent prose is misleading, the sample is 1980–1992, and the underlying INTEC study was not independently obtained. No headline statistic is used. [US7587325B1, historical failure table](https://patents.google.com/patent/US7587325B1/en). |
| SOHO had a precursor in telemetry for months | Use as an overlooked-configuration example. Three of four battery discharge regulators had been disconnected for months without recognition. The board explicitly found no evidence this caused or aggravated the attitude loss; it might have shortened subsequent telemetry transmission. Do not imply this was a proven cause, a validated warning lead time, or something our model would have detected. [NASA–ESA SOHO investigation, printed p. 10 / PDF p. 13](https://llis.nasa.gov/llis_lib/pdf/1009465main1_0664-mr.pdf#page=13). |

## Source-handling notes

The 59% figure is in the original paper body, not a ResearchGate recommendation or generated summary. For the cost study, ResearchGate's attached PDF does not match the surrounding 2013 metadata; the PDF's own title, conference date, and results govern the website wording. The earlier deployables PDF was searchable but direct retrieval returned an access error, so the directly readable conference paper is used instead. Sources are linked beside the corresponding website claims.

The SOHO story is not the cinematic re-entry story. The animation remains a fictional illustration, not a reconstruction of that mission. Dataset channels must not be assigned to a physical subsystem based on these aggregate statistics alone; the research pipeline retains its own documented channel metadata and assumptions.

## Video and framework decision

The user no longer wants a standalone film player. Its navigation, modal, and download CTA have been removed. Existing generated video files are preserved in ignored `archive/films/`; the old export utility was removed with the HTML-string entry point. No new film was generated during the migration.

The frontend has now been migrated to Next.js App Router + React + TypeScript. Static copy and evidence are server-rendered; scrolling, the canvas and interactive consoles are client components. The original Three.js visual is retained behind an interchangeable renderer interface. A separate mission-control route and authenticated server-side adapter prepare for a future inference worker; they do not imply that a trained model is already connected. [Next.js server/client component documentation](https://nextjs.org/docs/app/getting-started/server-and-client-components).

For a more photographic hero, the proposed pipeline is: an approved, text-free cinematic master → optimized desktop/mobile frame sequences → scroll-indexed canvas → HTML text overlays. Do not use the previous text-baked showcase film as that master. Frame sequences give explicit frame selection but need incremental preloading, a bounded decoded-frame cache, responsive resolution, and a reduced-motion poster. Start with a short sample and measure loading and memory before choosing all-frame delivery over an appropriately encoded scrubbed video. Direct video seeking has accuracy/browser tradeoffs; [`fastSeek()` explicitly trades accuracy for speed and is not universally available](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/fastSeek).

The **OpenAI Docs** skill was used to check current video generation. The official guide and API reference state that Sora 2 and the Videos API are deprecated and scheduled to shut down on **2026-09-24**. A saved visual asset should remain provider-independent. No assumption is made about this user's Sora access, and no replacement OpenAI video model is inferred. [Official video guide](https://developers.openai.com/api/docs/guides/video-generation), [create-video reference](https://developers.openai.com/api/reference/typescript/resources/videos/methods/create).
